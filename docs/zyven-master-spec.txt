Quero que você desenvolva um SaaS completo de social commerce para produtos digitais, comunidades, assinaturas e serviços.

A proposta central do produto é:

“Crie qualquer oferta e venda pelas suas redes sociais.”

O sistema deve permitir que creators, infoprodutores, agências e vendedores criem uma oferta, compartilhem um link nas redes sociais, recebam pagamentos e façam a entrega automaticamente.

IMPORTANTE:

A aplicação NÃO deve ser centrada em Telegram.

Telegram, Discord, links, arquivos, área de membros e webhooks devem ser apenas formas diferentes de entrega.

O núcleo da arquitetura deverá ser:

Offer
→ Checkout
→ Payment
→ Fulfillment

O objetivo é construir uma plataforma escalável, multi-tenant, moderna e preparada para produção.

A plataforma terá gateway próprio integrado.

Não copiar código, identidade visual, textos, marca, assets ou layout de nenhuma empresa existente.

==================================================
74. PRIMEIRO FLUXO END-TO-END OBRIGATÓRIO
==================================================

O primeiro fluxo funcional completo deverá ser:

1. usuário cria conta
2. cria Organization
3. cria Product
4. cria Offer
5. define fulfillment EXTERNAL_LINK
6. publica oferta
7. cliente abre página pública
8. inicia checkout
9. PIX é criado
10. webhook simulado confirma pagamento
11. ledger registra pagamento
12. saldo do merchant é atualizado
13. Entitlement é criado
14. Fulfillment é executado
15. cliente recebe link
16. dashboard registra venda

Somente depois desse fluxo funcionar ponta a ponta, expandir para integrações adicionais.

==================================================
75. IMPORTANTE
==================================================

Não trate Telegram como entidade central.

Telegram é apenas um Fulfillment/Integration.

Não trate checkout como simples tela.

Checkout é uma sessão de venda persistente.

Não trate saldo como campo editável.

O ledger é a fonte autoritativa.

Não trate pagamento como confiável até confirmação server-side.

Não implemente regras financeiras críticas no frontend.

Não confie em valores enviados pelo cliente.

Não permita cross-tenant access.

Não permita webhook duplicado gerar efeito duplicado.

Não permita saque concorrente consumir saldo duas vezes.

Comece pela FASE 1 e avance sequencialmente.
